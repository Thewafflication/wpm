\def\TCID{TC-0013}
\def\TCTitle{Version-aware package installation and upgrades}
\def\TCPurpose{Verify installed-state discovery, exact architecture and version selectors, configurable prerelease eligibility, SemVer ordering, upgrade validation and auditing, failure recovery, self-contained cached handoff, and best-effort multi-package behavior.}
\def\TCPriority{\TCPriorityHigh}
\def\TCRequirementRef{REQ-0013}
\def\TCDesignRef{ADR-0004 dependency resolution and version constraints}
\def\TCFeatureRef{\texttt{wpm/main.c} and \texttt{tests/tc-0013-version-aware-upgrades.ps1}}
\def\TCTestTechnique{Decision-table, boundary-value, and state-transition testing of SemVer ordering, selectors, architectures, and upgrade outcomes.}
\def\TCAssumptions{Controlled offline indexes and package archives are authoritative for candidate-selection scenarios.}
\def\TCInitialState{The isolated data root contains only the baseline packages installed by this test before upgrade evaluation.}
\def\TCPreconditions{A built WPM executable is available. The test uses an isolated WPM data-root override and controlled offline repository caches.}
\def\TCEnvironment{Local Windows developer workstation or CI worker.}
\def\TCInputData{Temporary packages covering x86, x64, and any architectures; stable and prerelease SemVer versions; successful and failing install scripts; controlled repository indexes; and an isolated prerelease configuration.}
\def\TCProcedure{\par\begin{enumerate}
\item Build and locally install baseline packages whose metadata creates independent x86, x64, and any installed identities.
\item Configure a controlled repository and seed its offline index and package cache with exact-architecture, any-architecture, stable, prerelease, selected-version, successful, and failing candidates.
\item Refresh repository data and verify that update reports eligible installed-package upgrades without applying them.
\item Decline an \texttt{upgrade --all} plan, accept a second plan by supplying \texttt{y} on standard input, then repeat with \texttt{-y} and verify that the plan, install-script output, and results remain visible.
\item Upgrade a package having installed x86 and x64 identities without an architecture selector.
\item Exercise named installation and upgrade with \texttt{--arch} and \texttt{--version}, including unavailable, equal, lower, and ZIP-path selector rejection.
\item Read and change the global prerelease setting, add and remove a per-package override, and perform stable and prerelease upgrades.
\item Attempt an any/specific installed-architecture conflict and verify that any candidates do not upgrade specific installed identities.
\item reject an unsigned upgrade before script execution, then explicitly permit it for the positive lifecycle scenarios.
\item Run a multi-package upgrade in which the first package script fails and a later package succeeds.
\item Upgrade WPM itself with no sidecar runtime in the candidate package and verify that the validated, self-contained executable is launched from cache, waits for the invoking WPM process to exit, and completes installation.
\item Inspect retained archives, staging cleanup, successful and failed upgrade audit records, command summaries, and exit statuses.
\item Run the companion \texttt{tests/file-processes-integration.py --wpm <executable> --holder <native-holder>} with default discovery and with \texttt{--legacy}. Hold a destination file open in a disposable process; list duplicate paths, exercise dry-run, reject invalid paths and options, explicitly terminate the holder, and overwrite the file while an unrelated process with the same executable remains running. Repeat discovery and termination for a private loaded DLL. Follow \texttt{docs/file-processes-legacy.md} for native Windows 2000/XP verification.
\item Run \texttt{tests/copy-integration.py --wpm <executable> --holder <native-holder>} with default discovery and \texttt{--legacy}. Exercise recursive and single-file copies, confirmation/cancellation, dry-run, changed plans, path and copy failures, protected ancestors and disposable destination file holders.
\item Run \texttt{tests/dependency-integration.py --wpm <executable>} with signed temporary packages. Exercise a diamond graph, multiple roots sharing a dependency, retained installed satisfaction, dependency upgrades, cancellation/dry-run, unavailable versions/architectures, cycles, and malformed declarations.
\end{enumerate}}
\def\TCExpectedResult{\par\begin{enumerate}
\item Installed identities are discovered from package metadata and the highest retained SemVer is treated as current.
\item Interactive \texttt{upgrade --all} accepts \texttt{y} from redirected standard input, while \texttt{n} cancels and \texttt{-y} bypasses the prompt.
\item x86 and x64 identities are upgraded independently; candidates must exactly match the installed architecture and an any candidate is ignored for a specific identity.
\item Named installation selectors choose the exact requested artifact. Upgrade selectors choose only a strictly newer exact version and never downgrade, reinstall, or silently fall back.
\item An any installation cannot coexist with specific architectures of the same package, and inconsistent state is diagnosed.
\item Prereleases are disabled by default, a package override takes precedence over the global value, stable releases remain eligible, and SemVer prerelease ordering is honored when enabled.
\item Build metadata alone does not cause an upgrade, and invalid repository versions do not prevent selection of valid candidates.
\item An unsigned or otherwise unvalidated candidate is rejected without script execution or successful installation state.
\item Successful upgrades retain both prior and new archives, clean staging, and create an audit record linking old and new versions.
\item A failed script preserves prior state, does not retain the candidate as successfully installed, cleans staging, creates a failure audit, and produces a nonzero result.
\item Multi-package processing continues after a failure, reports each identity as upgraded, current, or failed, and returns nonzero when any identity fails.
\item WPM self-upgrade uses a unique cached candidate executable to complete replacement after the original process releases the installed executable, even when a stale non-overwritable legacy cache entry exists.
\item Self-upgrade reports \texttt{scheduled} in the invoking process and records install-script output plus the final result in its persistent log.
\item The cached candidate accepts the legacy eight-argument self-upgrade handoff used by earlier WPM releases.
\item The cached candidate starts and completes installation without a private sidecar runtime.
\item File-user discovery reports the holder once. Listing and dry-run preserve it; explicit kill waits for its exit and permits replacement without stopping the unrelated process. Invalid arguments fail before termination and the utility creates no WPM data root. Inspection confirms PID creation-time checks, protected-process and ancestor exclusions, dynamic Restart Manager loading, and cleanup of process and session handles.
\item The companion \texttt{tests/copy-integration.py} runs with default and forced legacy discovery. Both \texttt{--recursive} and \texttt{-r} copy nested contents and empty directories to the exact destination and retain destination-only files. Negative, empty and EOF input cancel without mutation. Affirmative confirmation and \texttt{-y} authorize copying; dry-run overrides mutation. Held destination files are discovered and their disposable holder stops only after confirmation. Unrelated and ancestor processes survive; a protected ancestor prevents replacement. Missing/invalid sources, overlaps, same-file hard links, junctions and file/directory conflicts fail before mutation; single-file and new-parent copies succeed. No WPM data root is created. Inspection verifies bounded traversal, short-name expansion, post-confirmation plan checks and propagation of actual copy failures (REQ-0013.041 through REQ-0013.043).
\item Dependencies deploy once in topological order, selecting the highest eligible SemVer and honoring prerelease/architecture policy. Preview and cancellation run no scripts. Upgrades satisfy dependencies before upgrading the parent. Missing requirements, cycles and malformed declarations fail without parent deployment (REQ-0013.044 through REQ-0013.046). Inspection confirms the 64-node graph bound and immutable input handles.
\end{enumerate}}
\def\TCPostConditions{All temporary package sources, archives, repository caches, deployment markers, configuration, audit data, and WPM data directories are removed.}
